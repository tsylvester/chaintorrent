# `non_convertibility` — interaction spec

Branch contract for the `non_convertibility` module of the `vectors` module of `apps/harness-crypto`: `non_convertibility` produces the cross-entitlement non-convertibility vector records, generic over the credential KEM its caller hands it — under the entitlement scope, per record a credential issued for the configured identity, its `is_valid` verdict against that identity's element and against another configured identity's element under the record's parameter set, and the uniforms the record drew; under the asset scope an empty set. Each branch states condition, decision, dependency call, and the exact return outcome. `S` below is `<K::Pairing as IPairingAdapter>::Scalar`.

## `non_convertibility`

`non_convertibility<'a, K: ICredentialKemAdapter>(deps: &NonConvertibilityDeps<'a, K>, params: NonConvertibilityParams, payload: NonConvertibilityPayload<'_>) -> NonConvertibilityReturn<K>`, the trusted form: every input is a typed value from the caller — a borrowed KEM and randomness source in `deps`, the count and the admitted scope in `params`, the configured identity bytes and the other configured identity bytes in `payload`.

| Branch | Condition | Decision | Dependency call | Outcome |
|---|---|---|---|---|
| scope not the entitlement scope | `params.scope` is `Asset` | an exhaustive `match` on `params.scope`, before any record | none | `Ok(NonConvertibilitySuccessReturn { vectors: Vec::new() })`, no draw made and no KEM method called |
| draw failed | `deps.random.fill_bytes(FillBytesParams, FillBytesPayload { length })` returns `Err(error)`, `length` `<S as ISampleUniformScalar>::UNIFORM_BYTES_LENGTH` | the fill result | `deps.random.fill_bytes`, once per draw | `Err(NonConvertibilityErrorReturn::FillBytes(error))`, the error unchanged |
| setup failed | `deps.kem.setup` returns `Err(error)` | the call result | `deps.kem.setup`, once per record | `Err(NonConvertibilityErrorReturn::Setup(error))`, the error unchanged |
| configured identity's derivation failed | `deps.kem.derive_identity` returns `Err(error)` for the configured identity | the call result | `deps.kem.derive_identity`, once per record for the configured identity | `Err(NonConvertibilityErrorReturn::DeriveIdentity(error))`, the error unchanged |
| other identity's derivation failed | `deps.kem.derive_identity` returns `Err(error)` for the other identity | the call result | `deps.kem.derive_identity`, once per record for the other identity | `Err(NonConvertibilityErrorReturn::DeriveOtherIdentity(error))`, the error unchanged |
| issuance failed | `deps.kem.issue` returns `Err(error)` | the call result | `deps.kem.issue`, once per record | `Err(NonConvertibilityErrorReturn::Issue(error))`, the error unchanged |
| computed | the scope is `Entitlement` and every record's calls succeed | the records assembled in index order | the draws and adapter calls stated below | `Ok(NonConvertibilitySuccessReturn { vectors })` |

### Scope

An exhaustive `match` on `params.scope`, before any record: `Asset` takes the scope branch — `Ok(NonConvertibilitySuccessReturn { vectors: Vec::new() })`, no draw made and no KEM method called; `Entitlement` takes `KemIdentity::Entitlement { canonical: payload.identity }` as the identity, `KemIdentity::Entitlement { canonical: payload.other_identity }` as the other identity, and `SetupScope::Entitlement` as the setup scope, and the records below run.

### Draw

Every draw is `deps.random.fill_bytes(FillBytesParams, FillBytesPayload { length: <S as ISampleUniformScalar>::UNIFORM_BYTES_LENGTH })`; a failure takes the draw-failed branch. A copy of `success.bytes.expose()` is appended to the record's `draws` and `success.bytes` is handed on as the uniform.

### Record

For each index from `0` below `params.count.get()`: three draws held as `master_uniform`, `u0_uniform`, and `u1_uniform`; `deps.kem.setup(SetupParams { scope: SetupScope::Entitlement }, SetupPayload { master_uniform, u0_uniform, u1_uniform })`; `deps.kem.derive_identity(DeriveIdentityParams, DeriveIdentityPayload { parameter_set: &setup.parameter_set, identity })`, `identity` the configured identity the scope match produced; then the same call with the other identity; a fourth draw and `deps.kem.issue(IssueParams, IssuePayload { parameter_set: &setup.parameter_set, master_scalar: &setup.master_scalar, identity_element: &derived.identity_element, uniform })`; `deps.kem.is_valid(IsValidParams, IsValidPayload { parameter_set: &setup.parameter_set, identity_element, credential: &issued.credential })` with the configured identity's element and then with the other identity's element, each returning `Result<_, Infallible>` and unpacked irrefutably. Each failure takes its branch, the callee error carried unchanged; the issuance randomness, the master scalar, the parameter set, and both identity elements are dropped with the record's scope.

No input and no failure mode of the official mocks reaches the issuance-failed branch, since the method's one flavor is `Sampling`, every draw is `UNIFORM_BYTES_LENGTH` long, and `MockIPairingAdapterFailureMode::SampleScalarWrongLength`, the one mode that refuses a sampling, refuses setup's master sampling before issuance is reached; the branch has no unit block. Likewise no input and no failure mode of the official mocks reaches the other-identity-derivation-failed branch, since both identities derive under one parameter set and through one hash-to-scalar adapter, so every refusal `derive_identity` returns for the other identity it returns first for the configured one, and `MockIHashToScalarAdapterFailureMode::SamplingRefused` refuses the configured identity's derivation; the branch has no unit block. Likewise no input and no failure mode of the official mocks yields `false` for the verdict against the configured identity's element, since every concrete of the KEM family and its mock concrete compute the pairing check over a credential `issue` returned for that element under the record's own parameter set, and no mode of the pairing family's mock concrete alters `pairing_product_is_one`; the verdict is `true`. The verdict `other_is_valid` is the one `is_valid` returns against the other identity's element, never a constant: `false` when the other identity bytes differ from the configured identity bytes, and `true` when they are equal.

The record's outcome is a `NonConvertibilityVector` with the `draws`, `issued.credential` as `credential`, the first verdict's `is_valid` as `is_valid`, and the second's as `other_is_valid`.

### Ordering

The scope, then the records in index order; within a record its draws in the order master, `u0`, `u1`, and issuance, each draw immediately before its consuming call, the configured identity's derivation before the other's and both before the issuance draw, then the verdict against the configured identity's element, then against the other's; the first failure returns; every uniform's and secret's `Secret` is cleared when it drops; no side effect beyond the draws and the adapter's own.
