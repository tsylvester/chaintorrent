# `rerandomization` — interaction spec

Branch contract for the `rerandomization` module of the `vectors` module of `apps/harness-crypto`: `rerandomization` produces the rerandomized-validity vector records, generic over the credential KEM its caller hands it — per record a parameter set set up under the admitted scope, the configured identity's element, an issued credential and its rerandomization, each credential's validity verdict under the record's parameter set and identity element, and the uniforms the record drew. Each branch states condition, decision, dependency call, and the exact return outcome. `S` below is `<K::Pairing as IPairingAdapter>::Scalar`.

## `rerandomization`

`rerandomization<'a, K: ICredentialKemAdapter>(deps: &RerandomizationDeps<'a, K>, params: RerandomizationParams, payload: RerandomizationPayload<'_>) -> RerandomizationReturn<K>`, the trusted form: every input is a typed value from the caller — a borrowed KEM and randomness source in `deps`, the count and the admitted scope in `params`, the configured identity bytes in `payload`.

| Branch | Condition | Decision | Dependency call | Outcome |
|---|---|---|---|---|
| identity not an asset identity hash's length | `params.scope` is `Asset` and `<[u8; ASSET_IDENTITY_HASH_LENGTH]>::try_from(payload.identity)` fails | an exhaustive `match` on `params.scope`, before any record | none | `Err(RerandomizationErrorReturn::AssetIdentityLength { actual })`, `actual` the identity's length |
| asset identity refused | `AssetIdentityHash::try_new(AssetIdentityHashConstructorParams { bytes })` returns `Err(error)`, `bytes` the converted array | the same match's `Asset` arm | `AssetIdentityHash::try_new` | `Err(RerandomizationErrorReturn::AssetIdentityHash(error))`, the error unchanged |
| draw failed | `deps.random.fill_bytes(FillBytesParams, FillBytesPayload { length })` returns `Err(error)`, `length` `<S as ISampleUniformScalar>::UNIFORM_BYTES_LENGTH` | the fill result | `deps.random.fill_bytes`, once per draw | `Err(RerandomizationErrorReturn::FillBytes(error))`, the error unchanged |
| setup failed | `deps.kem.setup` returns `Err(error)` | the call result | `deps.kem.setup`, once per record | `Err(RerandomizationErrorReturn::Setup(error))`, the error unchanged |
| derivation failed | `deps.kem.derive_identity` returns `Err(error)` | the call result | `deps.kem.derive_identity`, once per record | `Err(RerandomizationErrorReturn::DeriveIdentity(error))`, the error unchanged |
| issuance failed | `deps.kem.issue` returns `Err(error)` | the call result | `deps.kem.issue`, once per record | `Err(RerandomizationErrorReturn::Issue(error))`, the error unchanged |
| rerandomization failed | `deps.kem.rerandomize` returns `Err(error)` | the call result | `deps.kem.rerandomize`, once per record | `Err(RerandomizationErrorReturn::Rerandomize(error))`, the error unchanged |
| computed | the identity is admitted and every record's calls succeed | the records assembled in index order | the draws and adapter calls stated below | `Ok(RerandomizationSuccessReturn { vectors })` |

### Identity

An exhaustive `match` on `params.scope`, before any record: `Entitlement` takes `KemIdentity::Entitlement { canonical: payload.identity }` as the identity and `SetupScope::Entitlement` as the setup scope; `Asset` first applies `<[u8; ASSET_IDENTITY_HASH_LENGTH]>::try_from(payload.identity)`, the failure taking the identity-length branch, then `AssetIdentityHash::try_new(AssetIdentityHashConstructorParams { bytes })`, a refusal taking the asset-identity branch; the identity is `KemIdentity::Asset { identity_hash: &hash }` and the setup scope `SetupScope::Asset { identity_hash: &hash }`.

### Draw

Every draw is `deps.random.fill_bytes(FillBytesParams, FillBytesPayload { length: <S as ISampleUniformScalar>::UNIFORM_BYTES_LENGTH })`; a failure takes the draw-failed branch. A copy of `success.bytes.expose()` is appended to the record's `draws` and `success.bytes` is handed on as the uniform.

### Record

For each index from `0` below `params.count.get()`: three draws held as `master_uniform`, `u0_uniform`, and `u1_uniform`; `deps.kem.setup(SetupParams { scope }, SetupPayload { master_uniform, u0_uniform, u1_uniform })`, `scope` the setup scope the identity match produced; `deps.kem.derive_identity(DeriveIdentityParams, DeriveIdentityPayload { parameter_set: &setup.parameter_set, identity })`, `identity` the identity the match produced; a fourth draw and `deps.kem.issue(IssueParams, IssuePayload { parameter_set: &setup.parameter_set, master_scalar: &setup.master_scalar, identity_element: &derived.identity_element, uniform })`; a fifth draw and `deps.kem.rerandomize(RerandomizeParams, RerandomizePayload { parameter_set: &setup.parameter_set, identity_element: &derived.identity_element, credential: &issued.credential, uniform })`; `deps.kem.is_valid(IsValidParams, IsValidPayload { parameter_set: &setup.parameter_set, identity_element: &derived.identity_element, credential })` with the issued credential and then with the rerandomized one, each returning `Result<_, Infallible>` and unpacked irrefutably. Each failure takes its branch, the callee error carried unchanged; the issuance randomness, the rerandomization offset, and the master scalar are dropped with the record's scope.

No input and no failure mode of the official mocks reaches the issuance-failed or rerandomization-failed branch, since each method's one flavor is `Sampling`, every draw is `UNIFORM_BYTES_LENGTH` long, and `MockIPairingAdapterFailureMode::SampleScalarWrongLength`, the one mode that refuses a sampling, refuses setup's master sampling before issuance is reached; neither branch has a unit block. Likewise no input and no failure mode of the official mocks yields `false` for either verdict, since every concrete of the KEM family and its mock concrete compute the pairing check over a credential `issue` or `rerandomize` returned for the record's own parameter set and identity element, and no mode of the pairing family's mock concrete alters `pairing_product_is_one`; each verdict is `true`.

The record's outcome is a `RerandomizationVector` with the `draws`, `setup.parameter_set` as `parameter_set`, `derived.identity_element` as `identity_element`, `issued.credential` as `issued`, `rerandomized.credential` as `rerandomized`, and the two verdicts' `is_valid` as `issued_is_valid` and `rerandomized_is_valid`.

### Ordering

The identity, then the records in index order; within a record its draws in the order master, `u0`, `u1`, issuance, and rerandomization, each draw immediately before its consuming call, then the issued credential's verdict, then the rerandomized credential's; the first failure returns; every uniform's and secret's `Secret` is cleared when it drops; no side effect beyond the draws and the adapter's own.

- `every_record_holds_true_verdicts_for_its_issued_and_rerandomized_credentials`: condition `rerandomization` over a case with a count above one, every adapter real and the operating-system source real; outcome for every record `issued_is_valid` and `rerandomized_is_valid` are `true`, `is_valid` run again over the record's parameter set, identity element, and each credential returns `true`, and the encoded `b` of `rerandomized` differs from that of `issued`; variation each case, each member of `PAIRING_CONCRETES` crossed with `DECLARED_HASH_TO_SCALAR_SELECTIONS` and with each selection and scope of `DECLARED_KEM_SELECTIONS`, so both curves and both scopes run; edge that must survive the composition: the rerandomized credential is formed without the master scalar, so a rerandomization that leaves its credential invalid, or returns the credential it was given, reports otherwise.
- `every_record_draw_replays_to_the_values_it_holds`: condition `rerandomization` over a case with a count of one, the record's `draws` split at `UNIFORM_BYTES_LENGTH` into the uniforms of its calls in draw order, and `setup`, `derive_identity`, `issue`, and `rerandomize` run on the case's KEM over those uniforms and the configured identity; outcome the replayed parameter set's `hpub`, the replayed identity element's `scalar` and `element`, and each replayed credential's `a` and `b`, each read through its components method and encoded through the case's pairing, equal those of the record's values; the record's `issued` `b` encodes to the `encode_g2` bytes of `mul_g2` of the second-group generator by the scalar sampled from the fourth uniform, and its `rerandomized` `b` to those of `add_g2` of the issued `b` and `mul_g2` of the generator by the scalar sampled from the fifth uniform; the record's identity element's `element` encodes through `encode_g1` to the encoding of `add_g1` of the record's `u0` and `mul_g1` of its `u1` by the identity element's `scalar`; variation every case, each run under two identity byte strings of its scope; edge that must survive the composition: draws in another order, or an identity other than the configured one, replay to other values; and, under the entitlement scope for each case of `DECLARED_HASH_TO_SCALAR_SELECTIONS` that declares `HashToScalarIdentifier::Keccak256V1`, the record's identity element's `scalar` encodes through `encode_scalar` to the encoding of the scalar the pairing's scalar type samples from `expected_uniform_bytes` over the tag built from `K::DECLARATION.identity_tag`, the configured identity bytes, and `UNIFORM_BYTES_LENGTH`.
