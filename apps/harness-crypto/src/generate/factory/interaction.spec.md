# `create_generate` — interaction spec

Branch contract for the `factory` module of the `generate` module of `apps/harness-crypto`: the generate family's construction point, which selects the concrete the configuration names, admits the borrowed encoder against the encoding identifier the selected concrete's declaration requires, admits the family's per-kind configuration against the declaration's kinds and sizings, builds each kind's size from the declared sizing and the configured quantities, constructs the concrete over the borrowed adapters, and hands it to a consumer generic over the family's trait and the delivery proof's forms. Each branch states condition, decision, dependency call, and the exact return outcome.

## `create_generate<'a, P, E, K, A, D, C: IGenerateConsumer<D::Forms>>(deps: &CreateGenerateDeps<'a, P, E, K, A, D, C>, params: CreateGenerateParams, payload: CreateGeneratePayload) -> CreateGenerateReturn<C::Output>`

The trusted form, the bounds the deps state. The entries are `params.kinds` in order, each yielding its `kind` and `quantities`; the decision is an exhaustive `match` on `&params.concrete`, so a variant with no arm fails to compile — the `Solidity { .. }` arm yielding `<SolidityGenerate<'a, P, E, K, A, D> as IGenerateAdapter>::DECLARATION`, and the `Mock(failure_mode)` arm, under `#[cfg(any(test, feature = "mocks"))]`, yielding the failure mode and `<MockIGenerateAdapter<D::Forms> as IGenerateAdapter>::DECLARATION`. The admission below runs once against the declaration the arm yields — the encoder first, then the params' kinds.

| Branch | Condition | Decision | Dependency call | Outcome |
|---|---|---|---|---|
| unsupported encoding identifier | `E::DECLARATION.identifier` is not the declaration's `encoding_identifier` | equality, read before any entry and before any construction | none | `Err(CreateGenerateErrorReturn::UnsupportedEncodingIdentifier)`, nothing constructed and the consumer not called |
| undeclared kind | no `VectorKindDeclaration` of the declaration's `kinds` has the entry's `kind` | slice membership, each entry in order | none | `Err(CreateGenerateErrorReturn::UndeclaredKind { kind })` |
| duplicate kind | an entry at a lower index has the same `kind` | the entries read in order | none | `Err(CreateGenerateErrorReturn::DuplicateKind { kind })` |
| missing quantity | the declared kind's `sizing` takes the quantity and the entry's `quantities` holds `None` for it | an exhaustive `match` on the sizing, which takes `count` for `Drawn`, `count` and `terms` for `DrawnTerms`, `count` and `message_length` for `DrawnMessages`, and none for `Enumerated` and `OverConfiguredInputs`; `count`, then `terms`, then `message_length` | none | `Err(CreateGenerateErrorReturn::MissingQuantity { kind, quantity })`, `quantity` the `VectorKindQuantity` of its name |
| unexpected quantity | the sizing does not take the quantity and the entry holds `Some` for it | the same match and order | none | `Err(CreateGenerateErrorReturn::UnexpectedQuantity { kind, quantity })` |
| missing kind | after every entry, no entry has the declared kind | each declared kind in declared order | none | `Err(CreateGenerateErrorReturn::MissingKind { kind })` |
| admitted | the encoder is admitted and every declared kind has exactly one admitted entry | an exhaustive `match` on `params.concrete` | the `Solidity { settings }` arm: `SolidityGenerate::try_new(SolidityGenerateConstructorParams { pairing: deps.pairing, hash_to_scalar: deps.hash_to_scalar, encoder: deps.encoder, random: deps.random, kem: deps.kem, key_agreement: deps.key_agreement, delivery_proof: deps.delivery_proof, render, constants, group_vectors, rejection_vectors, mapping_vectors, possession_vectors, challenge_vectors, proof_vectors, each the real function of its module as the handle of its field, statement_version: params.statement_version, settings: *settings, sizes })`, once, `sizes` the admitted entries' sizes in declared order, its success destructured irrefutably because its error arm is uninhabited, its `Forms` `D::Forms`; the `Mock(failure_mode)` arm: `MockIGenerateAdapter::<D::Forms>::try_new(MockIGenerateAdapterConstructorParams { failure_mode })`, once, its success destructured irrefutably because its error arm is uninhabited, the mock concrete holding no sizes; then, in either arm, `deps.consumer.consume_generate(ConsumeGenerateParams, ConsumeGeneratePayload { adapter })`, once | `Ok(CreateGenerateSuccessReturn { output })` |

## Ordering and invariants

- The encoding identifier check; then the entries in order, each checked for an undeclared kind, then a duplicate, then its quantities, before the next; then the missing kinds; then construction; then the consumer. The first refusal returns.
- An admitted entry's size is `VectorKindSettings { kind, size }`, `size` the `VectorKindSize` variant of the sizing's name holding the quantities the sizing takes.
- `params.concrete` selects the concrete and yields the declaration every check runs against; `params.kinds` is the family's per-kind configuration; `params.statement_version` is the delivery-statement version the hash-card names.
- `payload` carries nothing and is not read.
- The deps' borrows are copied into the constructor params; the deps are unchanged.
- The consumer is generic over `G: IGenerateAdapter<Forms = F>` for its own `F: IChainForms`; it receives only a concrete whose `Forms` are its own and never names the concrete.

## Integration: own entries

Each entry is proven by the private integration block of the same name in `integration_test.rs`, except `a_kinds_configured_count_reaches_the_concrete_as_the_records_its_file_holds`, proven by the public integration block of the same name in `tests/generate_integration_test.rs`.

- `emit_returns_a_distinct_path_for_every_kind_the_declaration_does_not_gate`: condition `emit` on the adapter `create_generate` hands the consumer for a member of `GENERATE_CONCRETES`, and for the mock selection, with the payload `build_emit_payload` builds over typed contexts in the consumer's forms and two distinct admitted identities under the scope the case's KEM reports, the first as the proof identity; outcome `Ok` whose `files` names no path twice and holds at least as many paths as the declaration the consumer reads from the adapter has kinds whose `requires_second_group_arithmetic` is `false`; variation every member of `GENERATE_CONCRETES` crossed with every member of `PAIRING_CONCRETES` and each scope of `DECLARED_KEM_SELECTIONS`, and the mock selection under `NoFailure`, whose declaration holds fewer ungated kinds than a real concrete's, so an `emit` that returns no path, or repeats one, fails; edge the paths are the concrete's own, a real concrete's written under the default root its settings builder names, a directory beneath the operating system's temporary directory, and the per-kind configuration the factory admitted for the real declaration's every kind is accepted by it.
- `a_refused_write_returns_the_mock_concretes_own_error`: condition `emit` on the adapter `create_generate` hands the consumer for `GenerateConcrete::Mock` carrying `MockIGenerateAdapterFailureMode::WriteRefused`; outcome `Err(EmitErrorReturn::Mock(MockIGenerateAdapterEmitErrorReturn::WriteRefused))`, the error asserted by a pattern naming every field because `EmitErrorReturn` omits `PartialEq`; variation the failure mode against `NoFailure`, which returns `Ok`; edge the mode is the one error arm no input reaches, selected only through configuration.
- `create_generate_refuses_an_encoder_declaring_another_encoding_identifier`: condition `create_generate` over an encoder whose declared encoding identifier is not the one the selected concrete's declaration requires; outcome `Err(CreateGenerateErrorReturn::UnsupportedEncodingIdentifier)` with the consumer never called; variation every member of `GENERATE_CONCRETES` over the encoding family's mock concrete, whose identifier is `EncodingIdentifier::Mock`, and the mock selection over each real concrete of `DECLARED_ENCODING_SELECTIONS`, so an admission that ignores the encoder, compares with a constant, or compares the wrong direction admits an encoder it must refuse; edge the refusal is decided from the encoder's own declaration and the selected concrete's own requirement.
- `a_kinds_configured_count_reaches_the_concrete_as_the_records_its_file_holds`: condition `create_generate` over the selection `build_generate_concrete` returns for a member of `GENERATE_CONCRETES` with `params.kinds` the configuration `build_generate_kind_configurations` returns for it, reversed, the possession entry's count overridden to a value other than the builder's default, every other count distinct from it, and a consumer that calls `emit`; outcome the `EmittedFile` whose `kind` is `Some(VectorKind::Possession)` holds a path whose file holds exactly the configured count of lines; variation every member of `GENERATE_CONCRETES` crossed with every member of `PAIRING_CONCRETES`, the entries reversed so sizes built in entry order give the possession kind another kind's count, and a count distinct from the default so a default size fails; edge the size the concrete reads is built from the declared sizing and the configured quantity, the file is found by its emitted kind tag — never a concrete's naming convention — and read from the real filesystem, and no expected value is read from the declaration or the pairing.

## Integration: private surface

The chain of real functions `create_pairing`, the arm's concrete through its `try_new`, `create_hash_to_scalar`, the selected concrete's `try_new` and `hash_to_scalar`, `create_encoding`, `create_chain_forms`, `create_kem`, `create_key_agreement`, `create_delivery_proof`, each selected concrete through its `try_new`, `create_random_source` for `RandomSourceKind::OperatingSystem`, `create_generate`, the selected concrete's `try_new`, `emit`, and the functions `emit` runs; the cases are every member of `PAIRING_CONCRETES` crossed with the selections `DECLARED_HASH_TO_SCALAR_SELECTIONS` that declare `HashToScalarIdentifier::Keccak256V1`, `DECLARED_ENCODING_SELECTIONS`, `CHAIN_FORMS_CONCRETES`, `DECLARED_KEM_SELECTIONS`, `DECLARED_KEY_AGREEMENT_SELECTIONS`, `DELIVERY_PROOF_CONCRETES`, and `GENERATE_CONCRETES`, and the mock selection; the outer-edge collaborators are the filesystem, a directory beneath the operating system's temporary directory, the operating system's generator running real, and the family's mock concrete under its failure mode for the refused-write entry alone; the observable result is the declaration, the `EmitReturn`, and the whole error; the entries proven are `emit_returns_a_distinct_path_for_every_kind_the_declaration_does_not_gate`, `a_refused_write_returns_the_mock_concretes_own_error`, and `create_generate_refuses_an_encoder_declaring_another_encoding_identifier`.

## Integration: public surface

An outside caller invokes `create_generate` with `CreateGenerateParams` from `harness_crypto`, a consumer implementing `IGenerateConsumer`, and the adapters the other families' factories hand it, selecting each concrete from `GENERATE_CONCRETES` and the other declared sets; it observes the `CreateGenerateReturn` and the files `emit` writes; the entry proven is `a_kinds_configured_count_reaches_the_concrete_as_the_records_its_file_holds`.
