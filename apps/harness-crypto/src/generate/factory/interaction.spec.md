# `create_generate` — interaction spec

Branch contract for the `factory` module of the `generate` module of `apps/harness-crypto`: the generate family's construction point, which selects the concrete the configuration names, admits the configuration's per-kind configuration against the concrete's declaration — every declared kind named exactly once, each with exactly the quantities its declared sizing takes — builds each kind's size from the declared sizing and those quantities, constructs the admitted concrete over borrowed collaborators, and hands it to a consumer generic over the family's trait. Each branch states condition, decision, dependency call, and the exact return outcome.

## `create_generate<'a, P, E, K, A, D, C: IGenerateConsumer>(deps: &CreateGenerateDeps<'a, P, E, K, A, D, C>, params: CreateGenerateParams, payload: CreateGeneratePayload) -> CreateGenerateReturn<C::Output>`

The trusted form; `P`, `E`, `K`, `A`, and `D` carry the bounds `CreateGenerateDeps` states — `P: IPairingArithmetic + IPairingReference`, `E: IEncoderAdapter`, `K: ICredentialKemAdapter<Pairing = P>`, `A: IKeyAgreementAdapter<Pairing = P>`, and `D: IDeliveryProofAdapter<Pairing = P>`.

Entries and declaration: the entries `params.kinds` in order, each yielding its `kind` and `quantities`, and an exhaustive `match` on `&params.concrete` — `Evm { settings }` and, under `#[cfg(any(test, feature = "mocks"))]`, `Mock(failure_mode)` — so a variant with no arm fails to compile. The `Evm { settings }` arm yields the settings and `<EvmGenerate<'a, P, E, K, A, D> as IGenerateAdapter>::DECLARATION`; the `Mock(failure_mode)` arm yields the failure mode and `<MockIGenerateAdapter as IGenerateAdapter>::DECLARATION`. The admission below runs once over the params' kinds against the declaration the arm yields.

| Branch | Condition | Decision | Dependency call | Outcome |
|---|---|---|---|---|
| undeclared kind | no `VectorKindDeclaration` of the declaration's `kinds` has the entry's `kind` | per entry, in entry order, before the next entry is read | none | `Err(CreateGenerateErrorReturn::UndeclaredKind { kind })`, `kind` the entry's; nothing constructed and the consumer not called |
| duplicate kind | an entry at a lower index has the same `kind` | per entry, after its undeclared check | none | `Err(CreateGenerateErrorReturn::DuplicateKind { kind })`; nothing constructed and the consumer not called |
| missing quantity | the declared kind's `sizing` takes the quantity and the entry's `quantities` holds `None` for it | an exhaustive `match` on `sizing` fixes the quantities it takes — `count` for `Drawn`, `count` and `terms` for `DrawnTerms`, `count` and `message_length` for `DrawnMessages`, and none for `Enumerated` and `OverConfiguredInputs` — then `count`, `terms`, and `message_length` are checked in that order | none | `Err(CreateGenerateErrorReturn::MissingQuantity { kind, quantity })`, `quantity` the `VectorKindQuantity` of its name; nothing constructed and the consumer not called |
| unexpected quantity | the sizing does not take the quantity and the entry's `quantities` holds `Some` for it | the same `sizing` match and the same quantity order, checked after the missing check of each name | none | `Err(CreateGenerateErrorReturn::UnexpectedQuantity { kind, quantity })`; nothing constructed and the consumer not called |
| admitted entry | none of the entry's checks refused | the entry's size is built from its declared sizing and its quantities | none | `VectorKindSettings { kind, size }`, `size` the `VectorKindSize` variant of the sizing's name holding the quantities it takes |
| missing kind | after every entry, a kind the declaration's `kinds` names has no entry | the declared `kinds` walked in declared order | none | `Err(CreateGenerateErrorReturn::MissingKind { kind })`; nothing constructed and the consumer not called |
| constructor refused | `try_new` returns `Err(error)` | the selected concrete's constructor runs once | `EvmGenerate::try_new(EvmGenerateConstructorParams { pairing: deps.pairing, hash_to_scalar: deps.hash_to_scalar, encoder: deps.encoder, random: deps.random, kem: deps.kem, key_agreement: deps.key_agreement, delivery_proof: deps.delivery_proof, scope: params.scope, statement_version: params.statement_version, settings, sizes })` | `Err(CreateGenerateErrorReturn::Evm(error))`, the refusal unchanged and the consumer not called; the error arm is `Infallible`, so no input takes this branch and it has no unit test |
| admitted | `try_new` returns `Ok(adapter)` | an exhaustive `match` on `params.concrete`, one arm per variant; the `Evm { settings }` arm constructs over the deps' adapters, `params.scope`, `params.statement_version`, `settings`, and `sizes`, the admitted entries' sizes in declared order, the constructor's success destructured irrefutably because its error arm is uninhabited | the arm's constructor call, once, then `deps.consumer.consume_generate(ConsumeGenerateParams, ConsumeGeneratePayload { adapter })`, once | `Ok(CreateGenerateSuccessReturn { output })` holding the consumer's output |

`Mock(failure_mode)` arm, under `#[cfg(any(test, feature = "mocks"))]`: the same admission over `<MockIGenerateAdapter as IGenerateAdapter>::DECLARATION` and the `kind` and `quantities` of each entry of `params.kinds` in order, each refusal the family's flavor the table's rows return; then `MockIGenerateAdapter::try_new(MockIGenerateAdapterConstructorParams { failure_mode })`, once, `failure_mode` the mode the `Mock` member of `params.concrete` carries, its success destructured irrefutably because its error arm is uninhabited, the mock concrete holding no sizes; then `deps.consumer.consume_generate(ConsumeGenerateParams, ConsumeGeneratePayload { adapter })`, once; the outcome is `Ok(CreateGenerateSuccessReturn { output })` holding the consumer's output.

## Ordering and invariants

- The entries in order, each checked for an undeclared kind, then a duplicate, then its quantities, before the next; then the missing kinds; then construction; then the consumer — the first refusal returns.
- `params.concrete` selects; `params.kinds` admit; `params.scope` and `params.statement_version` configure the constructed concrete; `payload` carries nothing and is not read.
- A kind's sizing is the concrete's declaration and is never configured; the factory builds each kind's `VectorKindSize` from the declared sizing and the entry's quantities.
- The deps' borrows are copied into the constructor params; the consumer is generic over `IGenerateAdapter` and never names the concrete.
- Adding a generate concrete is its module, its variant in `GenerateConcrete`, its entry in `GenerateConcreteKind` and `GENERATE_CONCRETES`, its variant in `CreateGenerateErrorReturn`, and its branch here — no consumer changes; the factory names no curve, count, name, path, version, or license.

## Integration: private surface

The chain of real functions `create_pairing`, the arm's concrete through its `try_new`, `create_hash_to_scalar`, the selected concrete's `try_new` and `hash_to_scalar`, `create_encoding`, `create_chain_forms`, `create_kem`, `create_key_agreement`, `create_delivery_proof`, each selected concrete through its `try_new`, `create_random_source` for `RandomSourceKind::OperatingSystem`, `create_generate`, the selected concrete's `try_new`, `emit`, and the functions `emit` runs; the cases are every member of `PAIRING_CONCRETES` crossed with the selections `DECLARED_HASH_TO_SCALAR_SELECTIONS` that declare `HashToScalarIdentifier::Keccak256V1`, `DECLARED_ENCODING_SELECTIONS`, `CHAIN_FORMS_CONCRETES`, `DECLARED_KEM_SELECTIONS`, `DECLARED_KEY_AGREEMENT_SELECTIONS`, `DELIVERY_PROOF_CONCRETES`, and `GENERATE_CONCRETES`, and the mock selection; the outer-edge collaborators are the filesystem, a directory beneath the operating system's temporary directory, the operating system's generator running real, and the family's mock concrete under its failure mode for the refused-write entry alone; the observable result is the declaration, the `EmitReturn`, and the whole error; the entries proven are `emit_returns_a_distinct_path_for_every_kind_the_declaration_does_not_gate` and `a_refused_write_returns_the_mock_concretes_own_error`.

## Integration: public surface

An outside caller invokes `create_generate` with `CreateGenerateParams` from `harness_crypto`, a consumer implementing `IGenerateConsumer`, and the adapters the other families' factories hand it, selecting each concrete from `GENERATE_CONCRETES` and the other declared sets; it observes the `CreateGenerateReturn` and the files `emit` writes; the entry proven is `a_kinds_configured_count_reaches_the_concrete_as_the_records_its_file_holds`.
