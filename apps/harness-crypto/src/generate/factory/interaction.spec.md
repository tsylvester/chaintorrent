# `create_generate` — interaction spec

Branch contract for the `factory` module of the `generate` module of `apps/harness-crypto`: the generate family's construction point, which selects the concrete the configuration names, admits the composition of the member the selection names against the declarations of the resolved chain forms and the borrowed encoder through the family's composition admission, admits the family's per-kind configuration against the declaration's kinds and sizings, builds each kind's size from the declared sizing and the configured quantities, constructs the concrete over the borrowed adapters, and hands it to a consumer generic over the family's trait and the delivery proof's forms. Each branch states condition, decision, dependency call, and the exact return outcome.

## `create_generate<'a, P, E, K, A, D, C: IGenerateConsumer<D::Forms>>(deps: &CreateGenerateDeps<'a, P, E, K, A, D, C>, params: CreateGenerateParams, payload: CreateGeneratePayload) -> CreateGenerateReturn<C::Output>`

The trusted form, the bounds the deps state. The entries are `params.kinds` in order, each yielding its `kind` and `quantities`; the decision is an exhaustive `match` on `&params.concrete`, so a variant with no arm fails to compile — the `Solidity { .. }` arm yielding `<SolidityGenerate<'a, P, E, K, A, D> as IGenerateAdapter>::DECLARATION`, and the `Mock(failure_mode)` arm, under `#[cfg(any(test, feature = "mocks"))]`, yielding the failure mode and `<MockIGenerateAdapter<D::Forms> as IGenerateAdapter>::DECLARATION`. The composition admission below runs once against the declaration's `identifier` and the received declarations, and the per-kind admission then runs against the declaration the arm yields.

| Branch | Condition | Decision | Dependency call | Outcome |
|---|---|---|---|---|
| incompatible composition | the call `(deps.admit_generate_composition)(&AdmitGenerateCompositionDeps { lookup_generate_declaration }, AdmitGenerateCompositionParams { identifier: declaration.identifier }, AdmitGenerateCompositionPayload { chain_forms: &<D::Forms as IChainForms>::DECLARATION, encoder: &E::DECLARATION })` returns `Err` | none of this function's | the family's composition admission, once, before any entry is read and before any construction | `Err(CreateGenerateErrorReturn::Composition(error))` carrying `AdmitGenerateCompositionErrorReturn` unchanged, with nothing constructed and the consumer not called; otherwise the function proceeds |
| undeclared kind | no `VectorKindDeclaration` of the declaration's `kinds` has the entry's `kind` | slice membership, each entry in order | none | `Err(CreateGenerateErrorReturn::UndeclaredKind { kind })` |
| duplicate kind | an entry at a lower index has the same `kind` | the entries read in order | none | `Err(CreateGenerateErrorReturn::DuplicateKind { kind })` |
| missing quantity | the declared kind's `sizing` takes the quantity and the entry's `quantities` holds `None` for it | an exhaustive `match` on the sizing, which takes `count` for `Drawn`, `count` and `terms` for `DrawnTerms`, `count` and `message_length` for `DrawnMessages`, and none for `Enumerated` and `OverConfiguredInputs`; `count`, then `terms`, then `message_length` | none | `Err(CreateGenerateErrorReturn::MissingQuantity { kind, quantity })`, `quantity` the `VectorKindQuantity` of its name |
| unexpected quantity | the sizing does not take the quantity and the entry holds `Some` for it | the same match and order | none | `Err(CreateGenerateErrorReturn::UnexpectedQuantity { kind, quantity })` |
| missing kind | after every entry, no entry has the declared kind | each declared kind in declared order | none | `Err(CreateGenerateErrorReturn::MissingKind { kind })` |
| admitted | the composition is admitted and every declared kind has exactly one admitted entry | an exhaustive `match` on `params.concrete` | the `Solidity { settings }` arm: `SolidityGenerate::try_new(SolidityGenerateConstructorParams { pairing: deps.pairing, hash_to_scalar: deps.hash_to_scalar, encoder: deps.encoder, random: deps.random, kem: deps.kem, key_agreement: deps.key_agreement, delivery_proof: deps.delivery_proof, render, constants, group_vectors, rejection_vectors, mapping_vectors, possession_vectors, challenge_vectors, proof_vectors, each the real function of its module as the handle of its field, statement_version: params.statement_version, settings: *settings, sizes })`, once, `sizes` the admitted entries' sizes in declared order, its success destructured irrefutably because its error arm is uninhabited, its `Forms` `D::Forms`; the `Mock(failure_mode)` arm: `MockIGenerateAdapter::<D::Forms>::try_new(MockIGenerateAdapterConstructorParams { failure_mode })`, once, its success destructured irrefutably because its error arm is uninhabited, the mock concrete holding no sizes; then, in either arm, `deps.consumer.consume_generate(ConsumeGenerateParams, ConsumeGeneratePayload { adapter })`, once | `Ok(CreateGenerateSuccessReturn { output })` |

## Ordering and invariants

- The match yielding the declaration, then the composition admission; then the entries in order, each checked for an undeclared kind, then a duplicate, then its quantities, before the next; then the missing kinds; then construction; then the consumer. The first refusal returns.
- An admitted entry's size is `VectorKindSettings { kind, size }`, `size` the `VectorKindSize` variant of the sizing's name holding the quantities the sizing takes.
- `params.concrete` selects the concrete and yields the declaration every check runs against; `params.kinds` is the family's per-kind configuration; `params.statement_version` is the delivery-statement version the hash-card names.
- `payload` carries nothing and is not read.
- The deps' borrows are copied into the constructor params; the deps are unchanged.
- The consumer is generic over `G: IGenerateAdapter<Forms = F>` for its own `F: IChainForms`; it receives only a concrete whose `Forms` are its own and never names the concrete.
