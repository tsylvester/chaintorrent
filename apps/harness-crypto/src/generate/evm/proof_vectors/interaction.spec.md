# proof_vectors interactions

`proof_vectors` produces the mint-proof and transfer-proof vector records the Solidity delivery verifier's Foundry tests prove against — the Solidity verifier must accept exactly what the Rust reference verifier accepts, bit for bit. For each of the configured counts, a mint record and a transfer record carrying the statement's context values in transcript order, every uniform the run drew, the precompile encodings of the statement's group elements, the proof's challenge and responses, and, under the first-group-only verifier form, the second-group first messages the verifier needs. The function reads no clock and touches no filesystem; it names no curve, concrete, form, count, scope, or context value — the counts and the identity scope arrive in its params, the canonical contexts, purposes, and identity bytes in its payload, and every adapter and encoding is the selection's.

## Description constructor

`MintProofVectorDescription::<F>::try_new(_params: MintProofVectorDescriptionConstructorParams) -> MintProofVectorDescriptionTryNewReturn<F>` and `TransferProofVectorDescription::<F>::try_new(_params: TransferProofVectorDescriptionConstructorParams) -> TransferProofVectorDescriptionTryNewReturn<F>`: one branch, outcome `Ok` of the description holding `PhantomData`.

## Context fields

Each record's context region is the fourteen kinds, in transcript order: `FixedBytes32`, `Unsigned16`, `<F::ChainIdentifier as ICanonicalField>::KIND`, `<F::Identity as ICanonicalField>::KIND`, `FixedBytes32`, `FixedBytes32`, `<F::Entitlement as ICanonicalField>::KIND` twice, `<F::Interval as ICanonicalField>::KIND` twice, `Unsigned16`, `<F::Identity as ICanonicalField>::KIND` twice, and `Unsigned64`. The context values of a record are `CanonicalFieldValue::FixedBytes32` of `suite_identifier`, `Unsigned16` of `suite_version`, clones of `chain` and `entitlement_contract`, `FixedBytes32` of `asset_identity_hash` and of `parameter_set`, clones of `source_entitlement`, `target_entitlement`, `old_interval`, and `new_interval`, `Unsigned16` of `purpose`, clones of `seller` and `buyer`, and `Unsigned64` of `expiry`.

## `members`

`members(&self) -> ProofVectorMembersReturn` on each description: for each index in order, dependency call `SolidityMemberName::try_new(SolidityMemberNameConstructorParams { text })` over the description's member names at that index — `MINT_PROOF_VECTOR_MEMBER_NAMES` or `TRANSFER_PROOF_VECTOR_MEMBER_NAMES`; a refusal returns `Err(ProofVectorMembersErrorReturn::MemberName(error))` unchanged; each admitted name paired with `FIELDS` at the same index as `SolidityRecordMember { name, kind }`; then `SolidityRecordMembers::try_new(SolidityRecordMembersConstructorParams { members })`, a refusal returning `Err(ProofVectorMembersErrorReturn::RecordMembers(error))` unchanged; otherwise `Ok` of the members. Every name is a distinct lower-camel identifier the constructor admits, other than `line`, so no input takes either refusal, and neither has a unit test.

### Identity

Decision an exhaustive `match` on `params.scope`, before any record: `IdentityScope::Entitlement` — the identity `KemIdentity::Entitlement { canonical: payload.identity }` and the setup scope `SetupScope::Entitlement`; `IdentityScope::Asset` — the identity-length branch where the conversion fails; else `AssetIdentityHash::try_new(AssetIdentityHashConstructorParams { bytes })`, a refusal taking the identity-hash branch, the identity `KemIdentity::Asset { identity_hash: &hash }` and the setup scope `SetupScope::Asset { identity_hash: &hash }`.

### Context

Per record, for the mint context with `relation` `DeliveryRelation::Mint` or the transfer context with `relation` `DeliveryRelation::Transfer`: a `DeliveryContext` whose domain values and `expiry` are clones from the canonical context, whose `purpose` is `payload.mint_purpose` or `payload.transfer_purpose`, and whose forms are rebuilt in transcript order — `<F::ChainIdentifier as ICanonicalField>::from_field(FromFieldParams, …)` over a clone of `chain`, `<F::Identity as ICanonicalField>::from_field` over a clone of `entitlement_contract`, `<F::Entitlement as ICanonicalField>::from_field` over clones of `source_entitlement` and `target_entitlement`, `<F::Interval as ICanonicalField>::from_field` over clones of `old_interval` and `new_interval`, and `<F::Identity as ICanonicalField>::from_field` over clones of `seller` and `buyer`; a refusal takes the form-refused branch — `ChainIdentifier { relation, error }` for `chain`, `Identity { relation, field, error }` with `field` `DeliveryContextField::EntitlementContract`, `Seller`, or `Buyer` for its fields, `Entitlement { relation, field, error }` with `field` `SourceEntitlement` or `TargetEntitlement`, and `Interval { relation, field, error }` with `field` `OldInterval` or `NewInterval`, each error carried unchanged.

### Record context

A `ProofVectorContext` read from the `DeliveryContext` before it is moved into the statement: `suite_identifier` a copy of `suite_identifier.identifier()`, `suite_version` its `version()`, each form-typed member the `CanonicalFieldValue` its form's `to_field(ToFieldParams, &form)` returns, unpacked irrefutably, `asset_identity_hash` a copy of `asset_identity_hash.as_bytes()`, `parameter_set` a copy of `parameter_set_identifier.as_bytes()`, `purpose` the purpose's `code()`, and `expiry` the context's.

### Draw

Dependency call `deps.random.fill_bytes(FillBytesParams, FillBytesPayload { length: <P::Scalar as ISampleUniformScalar>::UNIFORM_BYTES_LENGTH })`, a failure taking the draw-failed branch; a copy of `success.bytes.expose()` appended to the record's draws and `success.bytes` handed on as the uniform.

### Scalar bytes

For any scalar, dependency call `deps.pairing.encode_scalar(EncodeScalarParams, EncodeScalarPayload { scalar })`, unpacked irrefutably; the scalar-length branch where `<[u8; 32]>::try_from(success.bytes.expose().as_ref())` fails, `actual` the encoding's length; otherwise the array. A first-group point's bytes are the `as_ref()` copy of `deps.pairing.encode_g1` over a clone of it, and a second-group point's the `encode_g2` bytes likewise, each unpacked irrefutably. Every concrete encodes a scalar to 32 bytes, the families' mock concretes included, so no input takes the refusal, and it has no unit test.

### Issued credential

The shared head of both records: three draws held as `master_uniform`, `u0_uniform`, and `u1_uniform`; dependency call `deps.kem.setup(SetupParams { scope }, SetupPayload { master_uniform, u0_uniform, u1_uniform })`, a failure taking the setup-failed branch; `deps.kem.derive_identity(DeriveIdentityParams, DeriveIdentityPayload { parameter_set: &setup.parameter_set, identity })`, a failure taking the derive-failed branch; a fourth draw and `deps.kem.issue(IssueParams, IssuePayload { parameter_set, master_scalar, identity_element, uniform })`, a failure taking the issue-failed branch; two draws as `x_uniform` and `y_uniform` and `deps.key_agreement.generate_keys(GenerateKeysParams, GenerateKeysPayload { x_uniform, y_uniform })` for the seller, a failure taking the key-generation branch; `key_pair_public_keys` over the seller's key pair, unpacked irrefutably, and `public_keys_from_components(PublicKeysFromComponentsParams, PublicKeysFromComponentsPayload { components, possession: &seller.possession })`, a failure taking the public-keys branch; `credential_components` over the issued credential, unpacked irrefutably, and `wrap_to(WrapToParams, WrapToPayload { public_keys: &seller_public, credential: components })`, a failure taking the wrap branch; each callee error carried unchanged.

### Mint records

For each index from `0` below `params.mint_count.get()`: the mint context and its record context, then the issued credential's steps; `parameter_set_components`, `identity_element_components`, `key_pair_public_keys` over the seller's key pair, and `envelope_components` over the envelope, each unpacked irrefutably, their `hpub`, `element`, `pk1` and `pk2`, and `c1`, `c2`, `d1`, and `d2` encoded into the record; the statement `AlgebraicMintStatement { context, hpub, identity_element: element, buyer_keys: the seller's public-key components, envelope: the envelope's components }`; `master_scalar_components` over the master scalar, unpacked irrefutably; dependency call `deps.delivery_proof.prove_mint(ProveMintParams, ProveMintPayload { master_scalar: components, credential_randomness: issued.randomness, coins: wrap.coins, statement: &statement })`, a failure taking the mint-proof branch.

### Mint proof components

Dependency call `deps.delivery_proof.proof_components(ProofComponentsParams, ProofComponentsPayload { proof: &minted.proof })`, unpacked irrefutably; decision an exhaustive `match`: `MintBothGroups { challenge, responses }` — `second_group_first_messages` empty; `MintFirstGroupOnly { challenge, responses, first_messages }` — `second_group_first_messages` the `encode_g2` bytes of `first_messages.hpub`, `d1`, and `d2` concatenated in that order; a transfer arm takes the wrong-relation branch with `relation: DeliveryRelation::Mint`; outcome a `MintProofVector` with the draws, the record context, the encoded points, and the scalar bytes of `challenge`, `responses.alpha`, `responses.r`, `responses.rho`, and `responses.sigma`.

### Transfer records

For each index from `0` below `params.transfer_count.get()`: the transfer context and its record context, then the issued credential's steps; two draws and `generate_keys` for the buyer, its public keys admitted by `key_pair_public_keys` and `public_keys_from_components`, each failure taking its branch as in the issued credential; `unwrap(UnwrapParams, UnwrapPayload { key_pair: &seller.key_pair, envelope: &wrap.envelope })` and `credential_from_components` over the unwrapped components, each unpacked irrefutably; a ninth draw and `deps.kem.rerandomize(RerandomizeParams, RerandomizePayload { parameter_set, identity_element, credential: &seller_credential, uniform })`, a failure taking the rerandomize branch; `credential_components` over the rerandomized credential and `wrap_to` over the buyer's public keys, a failure taking the wrap branch; `identity_element_components`, `key_pair_public_keys` over each party's key pair, and `envelope_components` over the old and the new envelope, each unpacked irrefutably and encoded into the record; the statement `AlgebraicTransferStatement { context, identity_element, seller_keys, buyer_keys, old_envelope, new_envelope }`; `key_pair_components` over the seller's key pair, unpacked irrefutably; dependency call `deps.delivery_proof.prove_transfer(ProveTransferParams, ProveTransferPayload { seller_secrets: components, offset: rerandomized.offset, coins: new_wrap.coins, statement: &statement })`, a failure taking the transfer-proof branch.

### Transfer proof components

`proof_components` over the transfer proof, unpacked irrefutably; decision an exhaustive `match`: `TransferBothGroups { challenge, responses }` — `second_group_first_messages` empty; `TransferFirstGroupOnly { challenge, responses, first_messages }` — `second_group_first_messages` the `encode_g2` bytes of `first_messages.pk2`, `d1`, and `d2` concatenated in that order; a mint arm takes the wrong-relation branch with `relation: DeliveryRelation::Transfer`; outcome a `TransferProofVector` with the draws, the record context, the encoded points, and the scalar bytes of `challenge`, `responses.x`, `responses.y`, `responses.s`, `responses.rho`, and `responses.sigma`.

### Ordering

The identity, then the mint records, then the transfer records; within a record its context, then its draws in the order master, `u0`, `u1`, issue, seller `x` and `y`, and for a transfer buyer `x` and `y` and the rerandomization, each draw immediately before its consuming call, then its proof and components; the first failure returns; every uniform's, secret's, and coin's `Secret` is cleared when it drops; no side effect beyond the draws and the adapters' own.
