# `proof_vectors` — interaction spec

Branch contract for the `proof_vectors` module of the `solidity` module of the `generate` module of `apps/harness-crypto`: `proof_vectors` emits the mint-proof and transfer-proof vector records, each a drawn kind — per mint record one mint delivery over the typed mint context and the admitted identity, and per transfer record a mint delivery followed by a transfer delivery over the typed transfer context, the mint delivery's parameter set and identity element, and its recipient as the holder; each record carrying its draws, its statement as its context values and its elements' precompile encodings, and its proof's components, the first-group-only form carrying its second-group first messages — beside the two record descriptions with their member names and the shared record context. Each function's branches state condition, decision, dependency call, and the exact return outcome.

## `MintProofVectorDescription<F>::try_new`

`try_new(_params: MintProofVectorDescriptionConstructorParams) -> MintProofVectorDescriptionTryNewReturn<F>`: one branch; outcome `Ok` of the description holding `PhantomData`.

## `TransferProofVectorDescription<F>::try_new`

`try_new(_params: TransferProofVectorDescriptionConstructorParams) -> TransferProofVectorDescriptionTryNewReturn<F>`: one branch; outcome `Ok` of the description holding `PhantomData`.

## `proof_vectors`

`proof_vectors<'a, P: IPairingAdapter, K: ICredentialKemAdapter<Pairing = P>, A: IKeyAgreementAdapter<Pairing = P>, D: IDeliveryProofAdapter<Pairing = P>>(deps: &ProofVectorsDeps<'a, P, K, A, D>, params: ProofVectorsParams, payload: ProofVectorsPayload<'_, D::Forms>) -> ProofVectorsReturn`, the trusted form: `F` below is `D::Forms`, which the return does not name. The function reads no clock and touches no filesystem; it names no curve, concrete, form, scope, count, identity, or context value; the counts arrive in its params, the typed contexts and the admitted identity in its payload, and every encoding is the selected pairing's.

| Branch | Condition | Decision | Dependency call | Outcome |
|---|---|---|---|---|
| mint refused | `mint` returns `Err(error)` | the call's return | `mint(&MintDeps { kem: deps.kem, key_agreement: deps.key_agreement, delivery_proof: deps.delivery_proof, random: deps.random }, MintParams, MintPayload { context: payload.mint, identity: payload.identity })` | `Err(ProofVectorsErrorReturn::Mint(error))`, the error unchanged |
| transfer refused | `transfer` returns `Err(error)` | the call's return | `transfer(&TransferDeps { kem: deps.kem, key_agreement: deps.key_agreement, delivery_proof: deps.delivery_proof, random: deps.random }, TransferParams, TransferPayload { context: payload.transfer, parameter_set: &minted.delivery.parameter_set, identity_element: &minted.delivery.identity_element, holder: &minted.delivery.recipient })` | `Err(ProofVectorsErrorReturn::Transfer(error))`, the error unchanged |
| scalar length | `<[u8; 32]>::try_from(success.bytes.expose().as_ref())` fails on an encoded scalar | the conversion's return | `deps.pairing.encode_scalar(EncodeScalarParams, EncodeScalarPayload { scalar })` | `Err(ProofVectorsErrorReturn::ScalarLength { actual })`, `actual` the encoding's length |
| wrong relation | `proof_components` returns a transfer variant over a mint proof or a mint variant over a transfer proof | the match's arm | `deps.delivery_proof.proof_components(ProofComponentsParams, ProofComponentsPayload { proof })` | `Err(ProofVectorsErrorReturn::ProofComponents { relation })`, the record's relation |
| computed | every delivery, encoding, and components call succeeds | none | the calls each subsection states | `Ok(ProofVectorsSuccessReturn { mint, transfer })`, each list in index order |

### Mint delivery

Dependency call `mint(&MintDeps { kem: deps.kem, key_agreement: deps.key_agreement, delivery_proof: deps.delivery_proof, random: deps.random }, MintParams, MintPayload { context: payload.mint, identity: payload.identity })`; a failure returns `Err(ProofVectorsErrorReturn::Mint(error))` unchanged.

### Transfer delivery

Dependency call `transfer(&TransferDeps { kem: deps.kem, key_agreement: deps.key_agreement, delivery_proof: deps.delivery_proof, random: deps.random }, TransferParams, TransferPayload { context: payload.transfer, parameter_set: &minted.delivery.parameter_set, identity_element: &minted.delivery.identity_element, holder: &minted.delivery.recipient })`; a failure returns `Err(ProofVectorsErrorReturn::Transfer(error))` unchanged; no input and no failure mode of the official mocks reaches this arm, since the mint delivery that precedes it calls every adapter and draws from the source the transfer delivery uses, and every mode that refuses a transfer-side call refuses the mint delivery's first.

### Record context

A `ProofVectorContext` read from the delivery statement's `context`: `suite_identifier` a copy of `suite_identifier.identifier()`, `suite_version` its `version()`, each form-typed value the field its form's `to_field(ToFieldParams, &form)` returns, unpacked irrefutably, `asset_root` and `parameter_set` copies of their `as_bytes()`, `purpose` the purpose's `code()`, and `expiry` the context's.

### Scalar bytes

For any scalar, dependency call `deps.pairing.encode_scalar(EncodeScalarParams, EncodeScalarPayload { scalar })`, unpacked irrefutably; condition `<[u8; 32]>::try_from(success.bytes.expose().as_ref())` fails, outcome `Err(ProofVectorsErrorReturn::ScalarLength { actual })`, `actual` the encoding's length; otherwise the array; a point's bytes are the `as_ref()` copy of `encode_g1` or `encode_g2` over a clone of it, unpacked irrefutably.

### Mint record

For each index from `0` below `params.mint_count.get()`: the mint delivery; the record context from its statement's `context`; the statement's `hpub`, `identity_element`, `buyer_keys.pk1` and `buyer_keys.pk2`, and `envelope.c1`, `envelope.c2`, `envelope.d1`, and `envelope.d2` encoded into the record; the draws a copy of the delivery's `draws`.

### Mint proof components

Dependency call `deps.delivery_proof.proof_components(ProofComponentsParams, ProofComponentsPayload { proof: &minted.delivery.proof })`, unpacked irrefutably; decision an exhaustive `match`: `MintBothGroups { challenge, responses }`, `second_group_first_messages` empty; `MintFirstGroupOnly { challenge, responses, first_messages }`, `second_group_first_messages` the `encode_g2` bytes of `first_messages.hpub`, `d1`, and `d2` concatenated in that order; a transfer arm returns `Err(ProofVectorsErrorReturn::ProofComponents { relation: DeliveryRelation::Mint })`; outcome a `MintProofVector` with the draws, the record context, the encoded points, and the scalar bytes of `challenge`, `responses.alpha`, `responses.r`, `responses.rho`, and `responses.sigma`.

### Transfer record

For each index from `0` below `params.transfer_count.get()`: the mint delivery, then the transfer delivery over it; the record context from the transfer statement's `context`; the transfer statement's `identity_element`, `seller_keys.pk1` and `seller_keys.pk2`, `buyer_keys.pk1` and `buyer_keys.pk2`, `old_envelope.c1`, `old_envelope.c2`, `old_envelope.d1`, and `old_envelope.d2`, and `new_envelope.c1`, `new_envelope.c2`, `new_envelope.d1`, and `new_envelope.d2` encoded into the record; the draws a copy of the mint delivery's `draws` followed by a copy of the transfer delivery's.

### Transfer proof components

Dependency call `deps.delivery_proof.proof_components(ProofComponentsParams, ProofComponentsPayload { proof: &transferred.delivery.proof })`, unpacked irrefutably; decision an exhaustive `match`: `TransferBothGroups { challenge, responses }`, `second_group_first_messages` empty; `TransferFirstGroupOnly { challenge, responses, first_messages }`, `second_group_first_messages` the `encode_g2` bytes of `first_messages.pk2`, `d1`, and `d2` concatenated in that order; a mint arm returns `Err(ProofVectorsErrorReturn::ProofComponents { relation: DeliveryRelation::Transfer })`; outcome a `TransferProofVector` with the draws, the record context, the encoded points, and the scalar bytes of `challenge`, `responses.x`, `responses.y`, `responses.s`, `responses.rho`, and `responses.sigma`.

### Ordering

The mint records, then the transfer records; within a mint record its mint delivery, then its record context, encodings, and proof components; within a transfer record its mint delivery, then its transfer delivery, then its record context, encodings, and proof components; the deliveries draw in the order master, `u0`, `u1`, issue, recipient `x` and `y`, and for a transfer buyer `x` and `y` and the rerandomization; the first failure returns; every delivery, with its witnesses and secrets, drops at the end of its record, each `Secret` cleared; no side effect beyond the deliveries' draws and the adapters' own.
