# `kem_consumer` — interaction spec

Branch contract for the `kem_consumer` module of the `run` module of `apps/harness-crypto`: `KemConsumer`, an `IKemConsumer` the run constructs once for the chain forms type it received over borrows of the pairing, hash-to-scalar adapter, encoder, and random source the earlier factories handed, borrows of the configured generate concrete, its kind configurations, and statements, and the configured key-agreement and delivery-proof selections, and hands to `create_kem` as the deps' consumer; handed the KEM adapter and the scope it admitted, it constructs one `KeyAgreementConsumer` over its values, the handed adapter, and that scope, and calls `create_key_agreement` once, relaying the factory's return — the key-agreement consumer's output or the factory's refusal — unchanged. Each branch states condition, decision, dependency call, and the exact return outcome.

## Ordering and invariants

- The key-agreement consumer's construction, then the one call to `create_key_agreement`; `params` carries nothing and is not read; there is no side effect of the consumer's own, every write being the generate concrete's; the KEM adapter is borrowed from the payload for the call and the scope read from it, neither held.
- The consumer calls `create_key_agreement` and no other factory, reads no clock, touches no filesystem itself, reads no declaration, and holds no literal; every value it hands `create_key_agreement` and the key-agreement consumer is its own configured value, a borrow the earlier factories handed, the handed adapter, or the admitted scope.
