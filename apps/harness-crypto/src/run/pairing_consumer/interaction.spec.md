# `pairing_consumer` — interaction spec

Branch contract for the `pairing_consumer` module of the `run` module of `apps/harness-crypto`: `PairingConsumer` is the run's consumer of the pairing family's factory — an `IPairingConsumer` constructed from the borrowed randomness source, the borrowed `AdmittedStatements` and `AdmittedIdentities`, the admitted hash-to-scalar, encoding, chain forms, KEM, and key agreement selections, the delivery proof selection, the generate selection with its per-kind configuration, the verifier concrete of the curve the consumer composes, the statement version, and the iteration count, which on receiving the pairing obtains the hash-to-scalar adapter for that pairing's scalar type through `create_hash_to_scalar`, constructs an `EncodingConsumer` over both, calls `create_encoding` with the held encoding selection, and returns the files written and the measurement, or the first refusal whole.
It names no concrete, reads no configuration, and admits no selection or identity.
Each branch states condition, decision, dependency call, and the exact return outcome.

## `PairingConsumer::try_new`

`PairingConsumer::try_new(params: PairingConsumerConstructorParams<'a>) -> PairingConsumerTryNewReturn<'a>`: the one producer of the consumer; the randomness source, the admitted statements, the admitted identities, and the configured values are required at creation, and no partially constructed consumer exists.

### Constructed

Outcome `Ok(PairingConsumer)` holding the params' randomness source, statements, identities, and configured values; the error arm is `Infallible` and has no branch.

## `consume_pairing`

`consume_pairing<P: IPairingArithmetic + IPairingReference>(&self, _params: ConsumePairingParams, payload: ConsumePairingPayload<P>) -> PairingConsumerReturn`, the trait method of `IPairingConsumer for PairingConsumer<'a>`, `type Output = PairingConsumerReturn`; the params carry nothing and are not read, and the payload's adapter is the pairing the consumer borrows.

### Hash-to-scalar refused

Dependency call `create_hash_to_scalar::<P::Scalar>(&CreateHashToScalarDeps, CreateHashToScalarParams { concrete: self.hash_to_scalar.concrete, identifier: self.hash_to_scalar.identifier }, CreateHashToScalarPayload)`, once; condition the call returns `Err(error)`; outcome `Err(PairingConsumerErrorReturn::CreateHashToScalar(error))`, `error` unchanged, and `create_encoding` not called.

### Encoding refused

Dependency call `create_encoding(&CreateEncodingDeps { consumer }, CreateEncodingParams { concrete: self.encoding.concrete, identifier: self.encoding.identifier }, CreateEncodingPayload)`, once, `consumer` the `EncodingConsumer` built by `EncodingConsumer::try_new(EncodingConsumerConstructorParams { pairing: &payload.adapter, hash_to_scalar: the returned adapter borrowed as the trait object, random: self.random, statements: self.statements, identities: self.identities, chain_forms: self.chain_forms, kem: self.kem, key_agreement: self.key_agreement, delivery_proof: self.delivery_proof, generate: self.generate.clone(), kinds: self.kinds.clone(), verifier: self.verifier.clone(), statement_version: self.statement_version, iterations: self.iterations })` through the irrefutable pattern `let Ok(consumer) = …;`; condition the call returns `Err(error)`; outcome `Err(PairingConsumerErrorReturn::CreateEncoding(error))`, `error` unchanged.

### Encoding consumer refused

Condition the call returns `Ok(CreateEncodingSuccessReturn { output })` and `output` is `Err(error)`; outcome `Err(PairingConsumerErrorReturn::Encoding(error))`, `error` unchanged.

### Consumed

Condition `output` is `Ok(success)`; outcome `Ok(success)`, the `DeliveryProofConsumerSuccessReturn` as the delivery proof consumer returned it through the key agreement, KEM, chain forms, and encoding consumers; the method compares, converts, and summarizes nothing.

### Ordering

`create_hash_to_scalar` is called before the `EncodingConsumer` is built and before `create_encoding`, each is called once, and the first refusal returns and nothing after it runs; the pairing the consumer is built over is the one borrow of `payload.adapter`, and the adapter it is built over is the one the factory returned; the held values are borrowed or cloned for the call and not altered.
