# `factory` — interaction spec

Branch contract for the `factory` module of the `envelope` crate: the key-agreement family's construction point, selecting the concrete the composition names, admitting it against the key-agreement identifier the hash-card names and the envelope algebra the suite's delivery proof requires, and handing it to a consumer generic over `IKeyAgreementAdapter` for the caller's pairing. Each branch states condition, decision, dependency call, and the exact return outcome.

## `create_key_agreement<'a, P: IPairingArithmetic, E: IEncoderAdapter, C: IKeyAgreementConsumer<P>>(deps: &CreateKeyAgreementDeps<'a, P, E, C>, params: CreateKeyAgreementParams, payload: CreateKeyAgreementPayload) -> CreateKeyAgreementReturn<C::Output>`

The decision is a `match` on `params.concrete`, one arm per `KeyAgreementConcrete` variant — `PairingElGamal` and, under `#[cfg(any(test, feature = "mocks"))]`, `Mock` — exhaustive, so a variant with no arm fails to compile. Each arm runs the same contract against the concrete it names.

| Branch | Condition | Decision | Dependency call | Outcome |
|---|---|---|---|---|
| unsupported identifier | the arm's declared identifier is not `params.identifier`, the `PairingElGamal` arm reading `PairingElGamalKeyAgreement::<'_, P, E>::DECLARATION.identifier` and the `Mock` arm reading the `DECLARATION.identifier` of `MockIKeyAgreementAdapter<'_, P>` | equality, read before any construction | none | `Err(CreateKeyAgreementErrorReturn::UnsupportedKeyAgreementIdentifier)`; nothing is constructed and the consumer is not called. The two arms declare different identifiers, so an input takes this branch in each arm |
| unsupported algebra | the identifier matches and the arm's `DECLARATION.algebra` is not `params.algebra` | equality, read before any construction | none | `Err(CreateKeyAgreementErrorReturn::UnsupportedEnvelopeAlgebra)`; nothing is constructed and the consumer is not called. `EnvelopeAlgebra` has the one variant both concretes declare, so no input takes this branch until a further algebra exists, and it has no unit test |
| constructor refused | both checks pass in the `PairingElGamal` arm and `PairingElGamalKeyAgreement::try_new(PairingElGamalKeyAgreementConstructorParams { pairing: deps.pairing, hash_to_scalar: deps.hash_to_scalar, encoder: deps.encoder, random: deps.random })` returns `Err(error)` | the constructor's result | `try_new` once | `Err(CreateKeyAgreementErrorReturn::PairingElGamal(error))`, the refusal unchanged, the consumer not called. The concrete's tags are admitted, so no input takes this branch and it has no unit test; the `Mock` arm's `try_new` carries `Infallible` in its error arm and has no refusal branch |
| admitted | the arm's `try_new` returns `Ok(adapter)`, the `Mock` arm constructing `MockIKeyAgreementAdapter::try_new(MockIKeyAgreementAdapterConstructorParams { pairing: deps.pairing, failure_mode })` with the failure mode its selection carries | none | `deps.consumer.consume_key_agreement(ConsumeKeyAgreementParams, ConsumeKeyAgreementPayload { adapter })`, exactly once, the consumer reading `K::DECLARATION` | `Ok(CreateKeyAgreementSuccessReturn { output })` holding the consumer's output |

`Mock` arm, under `#[cfg(any(test, feature = "mocks"))]`: the same admission over the mock concrete's declaration constant — `MockIKeyAgreementAdapter::<'_, P>::DECLARATION.identifier` against `params.identifier`, then `DECLARATION.algebra` against `params.algebra`; then `MockIKeyAgreementAdapter::try_new(MockIKeyAgreementAdapterConstructorParams { pairing: deps.pairing, failure_mode })` once, `failure_mode` the mode the `Mock` member of `params.concrete` carries, its success destructured irrefutably because its error arm is `Infallible`; the outcome is as the admitted branch, holding the mock adapter.

The `PairingElGamal` variant of `CreateKeyAgreementErrorReturn` carries `PairingElGamalKeyAgreementTryNewErrorReturn`, that concrete's constructor error, in the return union unchanged; each further concrete's constructor refusal is its own variant. The `Mock` arm constructs no error variant, its constructor's error arm being uninhabited.

## Ordering and edges

- `params.concrete` selects the concrete; `params.identifier` and `params.algebra` admit or refuse it. `payload` carries nothing and is not read.
- The identifier check precedes the algebra check and both precede construction in every arm: a refused concrete is never constructed, and `deps.consumer` is never touched.
- The deps' borrows are copied into the constructor params and the deps are unchanged.
- The consumer is generic over `K: IKeyAgreementAdapter<Pairing = P>` for the caller's pairing `P`; it is instantiated for the concrete the arm constructs and never names the concrete itself.

## Integration: callee dispositions

- `libraries_sharing_an_identifier_flatten_a_first_group_statement_to_the_same_fields` (`envelope/possession_statement`, carried by `envelope/pairing_elgamal`): carried — restated in this node's terms: the fields a description flattens a possession statement to are the bytes the encoder returns and the challenge step hashes, so on any libraries sharing an identifier a proof of possession's challenge, computed by the adapter `create_key_agreement` hands the consumer, is over equal bytes, so `generate_keys` over equal draws and equal nonce draws on any two pairing concretes whose declarations carry the same `target_group_encoding` returns possession components that encode to equal bytes in each group; route `create_pairing` for each library, `create_encoding`, `create_hash_to_scalar`, `create_random_source` selecting the mock concrete under `Succeeds`, `create_key_agreement`, the arm's concrete through its `try_new`, `consume_key_agreement`, the description's `try_new`, `to_fields`, `encode_g1` or `encode_g2`, the encoder's `encode`, then `generate_keys` at its challenge step; the outer-edge collaborator on the route is the randomness family's mock concrete under `Succeeds`, one fresh instance per library, so the nonce draws are the same on each library.
- `libraries_sharing_an_identifier_flatten_a_second_group_statement_to_the_same_fields` (`envelope/possession_statement`, carried by `envelope/pairing_elgamal`): carried — restated and routed as the first-group entry, over the second-group statement's description, `to_fields`, and `encode_g2`.

## Integration: private surface

The chain of real functions `create_pairing`, `create_encoding`, the selected encoding concrete's `encode`, `create_hash_to_scalar`, the selected concrete's `hash_to_scalar`, `create_random_source` for `RandomSourceKind::OperatingSystem`, `create_key_agreement`, the selection's concrete through its `try_new`, and every method of the adapter an entry names, with `Secret` of `domain` running for real; the cases are every member of `DECLARED_KEY_AGREEMENT_SELECTIONS` and the mock selection, each over every member of `PAIRING_CONCRETES`, with every selection of `DECLARED_ENCODING_SELECTIONS` and `DECLARED_HASH_TO_SCALAR_SELECTIONS` handed to the real concretes; no outer-edge collaborator is mocked, the mock concrete being a case the family's factory selects and the operating system's generator behind `create_random_source` running real; the observable result is each method's `Result` and the scalars and points the entries compare through `encode_scalar`, `encode_g1`, and `encode_g2`; the entries proven are every own contract entry above and `a_refused_nonce_draw_returns_the_mock_error_whole` and `a_refused_coin_draw_returns_the_mock_error_whole`.

## Integration: public surface
