# `factory` — interaction spec

Branch contract for the `factory` module of the `encoding` crate: `create_encoding`, the encoding family's construction point, which reads the declaration the family's declaration lookup returns for the selection, constructs the concrete the admitted selection names, and hands it to a consumer generic over the family's encoder and decoder traits. Each branch states condition, decision, dependency call, and the exact return outcome.

## `create_encoding<C: IEncodingConsumer>(deps: &CreateEncodingDeps<C>, params: CreateEncodingParams, payload: CreateEncodingPayload) -> CreateEncodingReturn<C::Output>`

The decision is first the declaration read, then a `match` on `params.selection`, one arm per `EncodingConcrete` variant, exhaustive so a variant with no arm fails to compile. `params.selection` selects and is the only input the declaration read and the `match` take; `payload` carries nothing and is not read; the factory compares no identifier.

### Declaration read

| Branch | Condition | Decision | Dependency call | Outcome |
|---|---|---|---|---|
| declaration read | every call | the declaration is read before any construction | `(deps.lookup)(&LookupEncodingDeclarationDeps, LookupEncodingDeclarationParams { concrete: params.selection }, LookupEncodingDeclarationPayload)` exactly once, its success destructured irrefutably because its error arm is uninhabited, its `declaration` held for the arm | none returned |

### `EncodingConcrete::Abi`

| Branch | Condition | Decision | Dependency call | Outcome |
|---|---|---|---|---|
| selected | `params.selection` is `EncodingConcrete::Abi` | the concrete is constructed | `AbiEncoding::try_new(AbiEncodingConstructorParams)` exactly once, its success destructured irrefutably because its error arm is uninhabited, then `deps.consumer.consume_encoding(ConsumeEncodingParams, ConsumeEncodingPayload { adapter, declaration })` exactly once with the declaration read | `Ok(CreateEncodingSuccessReturn { output })` holding the consumer's output |

`CreateEncodingErrorReturn::Abi` carries the constructor's uninhabited error type in the return union, so no branch produces it.

### `EncodingConcrete::Mock` — under `#[cfg(any(test, feature = "mocks"))]`

| Branch | Condition | Decision | Dependency call | Outcome |
|---|---|---|---|---|
| selected | `params.selection` is `EncodingConcrete::Mock` | no constructor, so no constructor error | `deps.consumer.consume_encoding(ConsumeEncodingParams, ConsumeEncodingPayload { adapter, declaration })` exactly once with `MockIEncoderAdapter` by value and the declaration read | `Ok(CreateEncodingSuccessReturn { output })` holding the consumer's output |

## Integration: own entries and callee dispositions

### Own entries

- **Every concrete is handed to the consumer under its own declaration.** Condition: `create_encoding` is called with the selection of a concrete and deps holding the real `lookup_encoding_declaration`. Outcome: `Ok(CreateEncodingSuccessReturn { output })` with `output.declaration` the declaration the consumer received in its payload, whose `concrete` is the selection passed, whose `identifier` is a member of `ENCODING_IDENTIFIERS`, and whose `interface_version` is `ENCODING_INTERFACE_VERSION`. Variation: each member of `ENCODING_CONCRETES` and the mock selection, whose declared `concrete` differs, so a lookup called with another selection than the one that chose the adapter, or a declaration read for another member, returns another `concrete`. Edge that must survive the composition: the declaration the consumer receives is read for the same selection that chose the adapter.
- **Every concrete decodes what it encodes.** Condition: `create_encoding` is called with the selection of a concrete, and the consumer encodes a field list through the concrete under the official description and decodes the bytes. Outcome: `output.round_trip` an `Ok(DecodeSuccessReturn { described })` whose `described` equals the field list encoded. Variation: each case of the declared set and the mock selection, whose byte forms differ, and a field list that differs from the builder's default in every value, so a concrete whose decode returns the default field list, or any value its bytes do not hold, fails. Edge that must survive the composition: the concrete the factory constructs is the one whose `encode` and `decode` the consumer calls.
- **Every concrete carries the reader's refusal of a field list one value short.** Condition: `create_encoding` is called with the selection of a concrete, and the consumer encodes a field list one value short of the description's `FIELDS`. Outcome: `output.encoded` equal to `Err(EncodeErrorReturn::Fields(CanonicalFieldReaderErrorReturn::Count { expected, actual }))`, no bytes written. Variation: each case of the declared set and the mock selection, so a concrete that encodes a field list the reader refuses fails. Edge that must survive the composition: the reader's refusal arrives whole in the family's `Fields` variant, naming the description's declared count and the emitted count.
- **Every concrete refuses bytes past a complete encoding.** Condition: `create_encoding` is called with the selection of a concrete, and the consumer decodes the bytes the concrete wrote for a field list followed by one extra byte. Outcome: `output.trailing_bytes` equal to `Err(DecodeErrorReturn::NonCanonical)`. Variation: each case of the declared set and the mock selection, so a concrete that accepts bytes past a complete encoding fails. Edge that must survive the composition: the extra byte is refused though the bytes before it are a complete encoding.
- **Every concrete refuses bytes that end inside an encoding.** Condition: `create_encoding` is called with the selection of a concrete, and the consumer decodes the bytes the concrete wrote for a field list with the last byte removed. Outcome: `output.truncated_bytes` an `Err` of `DecodeErrorReturn`. Variation: each case of the declared set and the mock selection, so a concrete that accepts bytes ending inside a field fails. Edge that must survive the composition: the refusal is returned though every byte present is a byte the concrete wrote.
- **Every concrete declaring the Ethereum ABI identifier encodes the reference fields to the reference vector.** Condition: `create_encoding` is called with the selection of a concrete whose declaration `lookup_encoding_declaration` returns carries `EncodingIdentifier::EthereumAbiV1`, and the consumer encodes the reference fields of the official description. Outcome: `output.encoded` an `Ok(EncodeSuccessReturn { bytes })` with `bytes` the known-answer vector authored from the ABI specification. Variation: the reference fields hold one value of each kind, distinct in every kind, a byte string and a text before the static items, so a swapped field, a wrong word width, or a misplaced tail changes the bytes. Edge that must survive the composition: the concrete the factory constructs is the one whose `encode` the consumer calls.
- **Every concrete declaring the Ethereum ABI identifier decodes the reference vector to the reference fields.** Condition: `create_encoding` is called with the selection of a concrete whose declaration `lookup_encoding_declaration` returns carries `EncodingIdentifier::EthereumAbiV1`, and the consumer decodes the reference vector under the official description. Outcome: `output.decoded` an `Ok(DecodeSuccessReturn { described })` with `described` equal to the reference fields. Variation: the same reference fields, so a field read from the wrong word or tail yields a refusal or an unequal field list. Edge that must survive the composition: the canonical re-encoding of the described fields equals the vector.
- **Every concrete names every canonical field kind.** Condition: `create_encoding` is called with the selection of a concrete, and the consumer asks the concrete for the name of each kind of the official description's `FIELDS`. Outcome: `output.type_names` holding one `EncodingTypeName` per kind in order, no two equal. Variation: each case of the declared set and the mock selection, with the official description holding one kind of each, so a concrete that names two kinds alike fails. Edge that must survive the composition: the names are read from the concrete the factory constructs and from no table of the consumer's.
- **Every concrete declaring the Ethereum ABI identifier names every kind by its ABI type.** Condition: `create_encoding` is called with the selection of a concrete whose declaration `lookup_encoding_declaration` returns carries `EncodingIdentifier::EthereumAbiV1`, and the consumer asks for the name of each kind of the official description's `FIELDS`. Outcome: `output.type_names` equal, in order, to `string`, `bytes`, `bytes32`, `uint16`, `uint32`, `uint64`, `bytes20`, and `uint256`. Variation: the official description's field kinds, one of each kind, so a swapped or missing name changes the list. Edge that must survive the composition: the fixed twenty-byte kind is `bytes20` and never `address`.
- **An admitted selection is handed to the consumer under its declaration.** Condition: `admit_encoding_selection` is called with a member of `ENCODING_CONCRETES` and `serde_json::Value::Null`, and `create_encoding` is called with the selection it returns and deps holding the real `lookup_encoding_declaration`. Outcome: `Ok(CreateEncodingSuccessReturn { output })` with `output.declaration.concrete` equal to the member passed to the admission. Variation: each member of `ENCODING_CONCRETES`, so an admission that returns another member's selection, or a factory that hands another concrete, returns another `concrete`. Edge that must survive the composition: the selection the admission returns is the selection the factory constructs.

### Callee dispositions

- **`declared_member_declaration_through_the_public_surface` of `encoding/lookup_encoding_declaration`: carried.** The property that survives this boundary is that the declaration handed to the consumer for a selection is that member's own declaration; route `create_encoding`, then the lookup the deps hold, ending at the declaration the consumer receives in its payload; outer-edge collaborators the consumer and the description it carries, mocked; proven by the entry `every concrete is handed to the consumer under its own declaration` in the public test.
- **`declared_member_selection_through_the_public_surface` of `encoding/admit_encoding_selection`: carried.** The property that survives this boundary is that the selection the admission returns for a member is the selection the factory constructs; route `admit_encoding_selection`, then `create_encoding`, ending at the declaration the consumer receives; proven by the entry `an admitted selection is handed to the consumer under its declaration` in the public test; the entry `supplied_setting_refused_through_the_public_surface` ends at no function and no test of this node, since the document the public test passes supplies no setting.

### Private surface

The chain of real functions `create_encoding`, the real `lookup_encoding_declaration` its deps hold, the selected concrete's constructor where it has one, and the concrete's `encode`, `decode`, and `type_name` as the consumer calls them, with the declaration the consumer receives in its payload. The entries proven privately are the handed-under-its-own-declaration, decodes-what-it-encodes, reader-refusal, trailing-bytes, truncated-bytes, and names-every-canonical-field-kind entries; the Ethereum ABI reference-vector encode, decode, and type-name entries and the admitted-selection entry are proven by the public test alone.

The `Abi` arm is proven by the unit block `create_encoding_reads_the_declaration_for_the_abi_selection_and_hands_it_to_the_consumer` and by the blocks run over `ENCODING_CONCRETES`; the outer-edge collaborators mocked are the consumer, replaced by the official `MockIEncodingConsumer`, and the description it carries, replaced by the official `MockIEncodingContract`; the cases are the members of `ENCODING_CONCRETES` and the mock selection; the observable result is the output `create_encoding` returns.

### Public surface

An outside caller invokes `create_encoding` with `CreateEncodingDeps` built over the official consumer mock carrying a description, the described value, and the bytes it operates on, a `CreateEncodingParams` whose `selection` is a member of `ENCODING_CONCRETES` or the selection `admit_encoding_selection` returns for one, deps holding the real `lookup_encoding_declaration`, and a `CreateEncodingPayload`, and observes the output it returns. The entries proven are the own entries above, each over the members of `ENCODING_CONCRETES`.
