# `factory` — interaction spec

Branch contract for the `factory` module of the `kem` crate: the credential KEM family's construction point, constructing the concrete the admitted selection names over the caller's borrowed pairing and hash-to-scalar adapter, after the composition admission has admitted it under the identity scope the suite requires, and handing it to a consumer generic over `ICredentialKemAdapter` for the caller's pairing. Each branch states condition, decision, dependency call, and the exact return outcome.

## `create_kem<'a, P: IPairingArithmetic, C: IKemConsumer<P>>(deps: &CreateKemDeps<'a, P, C>, params: CreateKemParams, payload: CreateKemPayload) -> CreateKemReturn<C::Output>`

The composition admission runs first, then the decision is a `match` on `params.concrete`, one arm per `KemConcrete` variant — `Bb1DepthOne` and, under `#[cfg(any(test, feature = "mocks"))]`, `Mock` — exhaustive, so a variant with no arm fails to compile. Each real arm runs the same contract against the concrete it names.

| Branch | Condition | Decision | Dependency call | Outcome |
|---|---|---|---|---|
| composition refused | `(deps.admit_kem_composition)` returns `Err(error)` | the admission's result, read before any construction | `deps.admit_kem_composition` once with `AdmitKemCompositionDeps { lookup_kem_declaration: deps.lookup_kem_declaration }`, `AdmitKemCompositionParams { concrete: params.concrete, scope: params.scope }`, and `AdmitKemCompositionPayload` | `Err(CreateKemErrorReturn::Composition(error))`, the refusal unchanged, with nothing constructed and the consumer not called |
| constructor refused | the composition admission returns `Ok` and `Bb1DepthOneKem::try_new(Bb1DepthOneKemConstructorParams { pairing: deps.pairing, hash_to_scalar: deps.hash_to_scalar })` returns `Err(error)` | the constructor's result | `try_new` once | `Err(CreateKemErrorReturn::Bb1DepthOne(error))`, the refusal unchanged, the consumer not called |
| admitted | `try_new` returns `Ok(adapter)` | none | `deps.consumer.consume_kem(ConsumeKemParams, ConsumeKemPayload { adapter, scope: params.scope })`, exactly once | `Ok(CreateKemSuccessReturn { output })` holding the consumer's output |

`Mock` arm, under `#[cfg(any(test, feature = "mocks"))]`: reached after the same composition admission, which the lookup answers for `KemConcrete::Mock` from the mock concrete's declaration; the dependency calls are `DomainTag::try_new` over the bytes of the mock concrete's identity tag constant, whose `Err(error)` is returned unchanged as `Err(CreateKemErrorReturn::MockICredentialKemAdapter(error))` with the consumer not called, then `MockICredentialKemAdapter::try_new(MockICredentialKemAdapterConstructorParams { pairing: deps.pairing, hash_to_scalar: deps.hash_to_scalar, tag })` once, its success destructured irrefutably because its error arm is uninhabited; the outcome is as the admitted branch, holding the mock adapter.

The `Composition` variant of `CreateKemErrorReturn` carries `AdmitKemCompositionErrorReturn`, the composition admission's refusal, in the return union unchanged; the `Bb1DepthOne` variant carries `Bb1DepthOneKemTryNewErrorReturn`, that concrete's constructor refusal, unchanged; the `MockICredentialKemAdapter` variant carries `DomainTagTryNewErrorReturn`, the refusal of the tag the mock concrete's identity tag constant builds, unchanged; each further concrete's constructor refusal is its own variant.

Branches no input reaches: the constructor refusal of `Bb1DepthOneKem::try_new` and the tag refusal of `DomainTag::try_new` in the `Mock` arm are decided by constants, `BB1_DEPTH_ONE_DECLARATION`'s identity tag and the mock concrete's identity tag constant, and by no field of the deps, params, or payload, and no failure mode of the official mocks selects either, so no block of this node reaches them and they are not integration entries.

## Ordering and edges

- The composition admission, then construction, then the consumer; `params.concrete` selects the concrete and, with `params.scope`, is admitted. `payload` carries nothing and is not read.
- A refused composition is never constructed, and `deps.consumer` is never touched.
- The deps' borrows are copied into the constructor params and the deps are unchanged.
- The consumer is generic over `K: ICredentialKemAdapter<Pairing = P>` for the caller's pairing `P`; it is instantiated for the concrete the arm constructs and never names the concrete itself. A consumer reads a declaration through `lookup_kem_declaration`.
