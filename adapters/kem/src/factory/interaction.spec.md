# `factory` — interaction spec

Branch contract for the `factory` module of the `kem` crate: the credential KEM family's construction point, selecting the concrete the composition names, admitting it against the KEM identifier and the identity scope the suite requires, and handing it to a consumer generic over `ICredentialKemAdapter` for the caller's pairing. Each branch states condition, decision, dependency call, and the exact return outcome.

## `create_kem<'a, P: IPairingArithmetic, C: IKemConsumer<P>>(deps: &CreateKemDeps<'a, P, C>, params: CreateKemParams, payload: CreateKemPayload) -> CreateKemReturn<C::Output>`

The decision is a `match` on `params.concrete`, one arm per `KemConcrete` variant — `Bb1DepthOne` and, under `#[cfg(any(test, feature = "mocks"))]`, `Mock` — exhaustive, so a variant with no arm fails to compile. Each real arm runs the same contract against the concrete it names.

| Branch | Condition | Decision | Dependency call | Outcome |
|---|---|---|---|---|
| unsupported identifier | the named concrete's `DECLARATION.identifier` is not `params.identifier` | equality, read before any construction | none | `Err(CreateKemErrorReturn::UnsupportedKemIdentifier)`; nothing is constructed and the consumer is not called. Under the `mocks` feature the mock concrete declares `KemIdentifier::Mock`, so a real concrete's selection paired with `Mock`, and the mock selection paired with another concrete's identifier, take this branch |
| unsupported scope | the identifier matches and the named concrete's `DECLARATION.identity_scopes` does not contain `params.scope` | `contains`, read before any construction | none | `Err(CreateKemErrorReturn::UnsupportedIdentityScope)`; nothing is constructed and the consumer is not called |
| constructor refused | both checks pass and `Bb1DepthOneKem::try_new(Bb1DepthOneKemConstructorParams { pairing: deps.pairing, hash_to_scalar: deps.hash_to_scalar })` returns `Err(error)` | the constructor's result | `try_new` once | `Err(CreateKemErrorReturn::Bb1DepthOne(error))`, the refusal unchanged, the consumer not called |
| admitted | `try_new` returns `Ok(adapter)` | none | `deps.consumer.consume_kem(ConsumeKemParams, ConsumeKemPayload { adapter, scope: params.scope })`, exactly once, the consumer reading `K::DECLARATION` | `Ok(CreateKemSuccessReturn { output })` holding the consumer's output |

`Mock` arm, under `#[cfg(any(test, feature = "mocks"))]`: the same admission over the mock concrete's declaration constant — `MockICredentialKemAdapter::DECLARATION.identifier` against `params.identifier`, then `DECLARATION.identity_scopes` against `params.scope`; the dependency calls are `DomainTag::try_new` over the bytes of the mock concrete's identity tag constant, whose `Err(error)` is returned unchanged as `Err(CreateKemErrorReturn::MockICredentialKemAdapter(error))` with the consumer not called, then `MockICredentialKemAdapter::try_new(MockICredentialKemAdapterConstructorParams { pairing: deps.pairing, hash_to_scalar: deps.hash_to_scalar, tag })` once, its success destructured irrefutably because its error arm is uninhabited; the outcome is as the admitted branch, holding the mock adapter.

The `Bb1DepthOne` variant of `CreateKemErrorReturn` carries `Bb1DepthOneKemTryNewErrorReturn`, that concrete's constructor refusal, in the return union unchanged; the `MockICredentialKemAdapter` variant carries `DomainTagTryNewErrorReturn`, the refusal of the tag the mock concrete's identity tag constant builds, unchanged; each further concrete's constructor refusal is its own variant.

## Ordering and edges

- `params.concrete` selects the concrete; `params.identifier` and `params.scope` admit or refuse it. `payload` carries nothing and is not read.
- The identifier check precedes the scope check, both precede construction, and construction precedes the consumer, in every arm: a refused concrete is never constructed, and `deps.consumer` is never touched.
- The deps' borrows are copied into the constructor params and the deps are unchanged.
- The consumer is generic over `K: ICredentialKemAdapter<Pairing = P>` for the caller's pairing `P`; it is instantiated for the concrete the arm constructs and never names the concrete itself.

## Integration: own entries

Each entry is proven by the private integration block of the same name in `factory/integration_test.rs`, over the cases stated in the private surface — except `a_kem_from_the_factory_round_trips_from_operating_system_draws`, proven by the public integration block of the same name in `tests/factory_integration_test.rs`.

- `every_concrete_is_constructed_under_the_identifier_and_scope_it_declares`: condition `create_kem` is called with a case's selection, the identifier that concrete declares, and a scope it declares; outcome `Ok(CreateKemSuccessReturn { output })`, `output` the consumer's reading of `K::DECLARATION.identifier` equal to `params.identifier`, of `K::DECLARATION.interface_version` equal to `KEM_INTERFACE_VERSION`, of `K::DECLARATION.identity_scopes` containing `params.scope`, and of `payload.scope()` equal to `params.scope`; variation each case, whose declared identifiers differ and each of whose declared scopes is run, so a construction of a concrete other than the selected one, or a scope other than the one required, reports otherwise; edge the adapter handed over computes over the borrowed pairing and hash-to-scalar adapter the deps hold.
- `every_concrete_is_refused_under_an_identifier_it_does_not_declare`: condition `create_kem` is called with a case's selection and the declared identifier of every other case whose declared identifier differs from its own; outcome `Err(CreateKemErrorReturn::UnsupportedKemIdentifier)` with the consumer not called; variation each case paired with each such identifier, so an admission that compares against a constant or ignores the selection admits a pairing it must refuse; edge the refusal is decided by the selected concrete's own declaration.
- `every_concrete_issues_a_credential_valid_for_its_identity`: condition `setup` under the case's scope, `derive_identity` over an identity of that scope, and `issue` with the master scalar `setup` returned; outcome `is_valid` returns `Ok(IsValidSuccessReturn { is_valid: true })`; variation `KemIdentity::Entitlement` under the entitlement scope and `KemIdentity::Asset` under the asset scope; edge the parameter set, master scalar, identity element, and credential agree across the methods.
- `every_concrete_rerandomizes_a_credential_to_one_valid_for_its_identity`: condition `rerandomize` over a credential `issue` returned, with no master scalar; outcome `is_valid` returns `true` for the rerandomized credential and for the credential it was made from; variation each scope; edge the offset `rerandomize` returned differs from the randomness `issue` returned.
- `every_concrete_decapsulates_a_well_formed_capsule_to_the_encapsulated_bytes`: condition `encapsulate` under the parameter set, then `decapsulate` with the issued credential and with the rerandomized credential; outcome `is_well_formed` returns `true` for the capsule and each `decapsulate` returns `key_material()` bytes equal to the bytes `encapsulate` returned; variation each scope, and under the asset scope an identity element of another asset identity passed to `decapsulate`; edge the value is encoded alike on both paths.
- `every_concrete_recovers_one_value_from_the_credentials_of_different_entitlements`: condition the entitlement scope, entitlements each `issue`d a credential, and `decapsulate` of one capsule with each; outcome each returns `key_material()` bytes equal to the bytes `encapsulate` returned; variation distinct canonical identity bytes; edge the identity scalar differs between the entitlements, so a decapsulation that dropped its identity term fails.
- `every_concrete_rejects_a_credential_for_another_identity_and_under_another_parameter_set`: condition `is_valid` over a credential `issue` returned, with the identity element of another identity and, separately, under a parameter set `setup` returned for other uniform bytes; outcome `Ok(IsValidSuccessReturn { is_valid: false })` for each; variation each scope; edge the same credential is valid for its own identity under its own parameter set.
- `every_concrete_rejects_a_capsule_with_exchanged_identity_base_elements`: condition the entitlement scope, a capsule `encapsulate` returned, read by `capsule_components`, its `v` and `w` exchanged, and rebuilt by `capsule_from_components`; outcome `is_well_formed` returns `false` for the rebuilt capsule and `true` for the original; variation the exchanged and the unexchanged capsule; edge the exchange is the only difference between them.
- `every_concrete_rejects_a_capsule_under_another_parameter_set`: condition `is_well_formed` over a capsule `encapsulate` returned, under a parameter set `setup` returned for other uniform bytes; outcome `false`, and `true` under its own parameter set; variation each scope; edge the same capsule is well formed under its own parameter set.
- `every_concrete_rejects_a_capsule_of_the_other_scope`: condition `is_well_formed` over an asset capsule under an entitlement parameter set and over an entitlement capsule under an asset parameter set, each capsule from a parameter set of its own scope; outcome `Ok(IsWellFormedSuccessReturn { is_well_formed: false })`; variation each direction, run for a case that declares both scopes; edge each capsule is well formed under its own scope's set.
